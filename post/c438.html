旧时代的船票

发表于2026-06-19|更新于2026-06-20|部落格
|字数总计:1.1k|阅读时长:3分钟

时代的眼泪

框架已经迎来了第三次大更新，

而我的博客，框架至今仍苟延残喘到在现在，还是22年当时自己亲自操刀的魔改版。

我恨我当年的天真，觉得自己的优化堪称完美，所有代码全走的外挂，全程没改动一行核心源码。

以为这样，到时候更新就直接升级就完事了，结果他妈的4.0版本直接就从底层的重构与优化，

我记得我当时看到推送的这条消息我人都傻了。

你这动底层代码重构不是直接挖我的坟么？

老子花了一个月时间，把一块地基建成了一栋楼，甚至觉得原来的不好修成了海景别墅，现在你告诉我升级需要推平重来?

作者你那婊子妈是不是死了。。。（此处省略一万字）

现在我的博客不是不愿意更新，而是更新完框架就直接崩了。。。（xsbb）

当年花一个月魔改的框架，到现在发现，竟然成了悬在我头顶的达摩克利斯之剑。

两难的问题：更新就崩、新的又得重新做不说，还舍不得当时自己改的劳动成果。

但是不更新吧，现在前端技术更新越来越快，这框架本来就是基于 Node.js 且采用单线程运行，

而且还没Pug 渲染引擎，如果到后期，每次本地预览或部署的生成时间会越来越长，体验就越来越差。

于是我觉得在这个版本里，无论是用第三方插件还是手写代码，都是在“强行给旧车装新配件”，不仅体验差，还容易引发系统崩溃。

而且升级处理代码合并冲突会非常繁琐，虽然每次升级可以通过外挂 CSS 覆盖层来缓解升级时的代码合并冲突。

但哥们那薄弱的前端 CSS 基础，实在经不起这样的折腾。

爬坑血泪史

就在昨天，最近刚更了一篇文章，发现本地预览呈现出来的一张张图片都老大了，界面和图片发生了错位，

我当时水都差点喷出来了。

界面加载说明可以排除页面框架没问题，那大概率就是页面渲染出问题了。

但是css怎么出问题了，我又没动它？

我当时都奇了怪了，其他文章界面都是好的。

结果排查来排查去，就差敲键盘了，结果发现页面渲染没问题，也是好的。。。

是文章界面有问题，但是我的Markdown语法没问题啊？

怎么回事？特么闹鬼了！

结果想一晚才发现曾经 Gallery 相册插件有问题，导致底层渲染引擎是“无法补全。

作者把Gallery相册插件内置到了4.2版本，就把之前的Gallery外挂插件长时间没维护就给删了。

然后Gallery 渲染机制没触发，然后遇到渲染阻塞时，就一直占用 CPU 直到超时。就把我页面给整崩了。

那一刻，不仅页面崩了，我的心态也彻底崩了。

作者是人我吃

觉醒吧，旧时代的残党！

我现在终于悟了。

在这个 Node.js 单线程的泥沼里，在旧框架上强行装第三方插件，简直就是强行给手扶拖拉机装航空发动机——不仅跑不快，还特么容易原地爆炸！

不更新？看着本地生成速度越来越慢，体验越来越差，就像看着自己的战舰慢慢生锈沉没。

更新？一想到要重写那些魔改的 CSS，但哥们那薄弱的前端 CSS 基础，实在经不起这样的折腾。
但是嘛，长痛不如短痛！

人总在跌跌撞撞中学会成长，或许现在这个决定在将来会是败笔，但是谁知道呢？

与其抱着那艘破船在旧时代的浅滩上搁浅，不如直接跳海，游向新时代的大航海！

干活！不就是重写 CSS 吗？不就是配置分离吗？

旧时代的船票？

我不在乎！

新时代没有能承载我的船？

那我就重自己造一艘！！！

又要更新咯。。。干活！
